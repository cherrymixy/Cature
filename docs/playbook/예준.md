# Cature 빌드 플레이북 — 예준 (Codex)

> 소유: **홈(지도) + 온보딩/Auth.** 도구: **Codex.**
> **시작 조건:** 승아가 `v0-contracts`(G1) 태그한 뒤. 그 전엔 S0 준비만.
> **철칙:** `HomeFeature`, `OnboardingFeature` 두 패키지 밖은 절대 건드리지 않는다. Core/Services/다른 Feature 수정 금지 — 필요하면 승아에게 계약 요청. Codex는 **각 패키지 디렉터리에서 실행**.

---

## S0 — 펜스 세팅 + mock/토큰 컴파일

**목적:** 내 패키지에 가드레일을 심고, mock 위에서 빈 화면이 도는지 확인.

**Codex 프롬프트(복붙 · HomeFeature 폴더에서 실행):**
```
지금 위치는 Packages/HomeFeature. 이 패키지 안에서만 작업한다.
이 폴더에 AGENTS.md를 만들어 규칙을 적어라:
- 작업 범위: 이 패키지 내부 파일만. Core/Services/다른 Feature/App 수정 금지.
- 데이터는 CorePackage 프로토콜(CollectionRepository, SightingRepository, SpeciesRepository, LocationService)로만 접근. 지금은 CorePackage/Mocks 사용.
- 스타일은 DesignTokens만(하드코딩 금지).
- 완료 전 mock 주입으로 컴파일·프리뷰 확인.
그다음 HomeFeature.RootView(빈 화면 + "홈" 라벨)를 만들고 Mock 프리뷰가 뜨는지 확인해라.
```
> OnboardingFeature도 `Packages/OnboardingFeature/AGENTS.md`를 동일 규칙(범위만 Onboarding, 데이터는 ProfileRepository)으로 만든다. RootView는 온보딩 진입.
**점검:** 두 패키지 mock+토큰 컴파일·프리뷰.
**커밋:** `chore(home,onboarding): package AGENTS.md + empty root views`

## S1 — 온보딩 · 권한 · Auth

**Codex 프롬프트(OnboardingFeature 폴더):**
```
Packages/OnboardingFeature 안에서만 작업.
온보딩 3~4스텝 슬라이드를 DesignTokens 기반으로 구현:
1) 주변의 생물을 발견해요  2) 이 생명을 알아봐요  3) 필요한 것/방해를 알게 돼요  4) 도감·지도에 수집하고 체험해요.
마지막에 시작 CTA. 진행 중 카메라·위치 권한 안내 카피(문구만; 실제 권한 요청은 승아 서비스가 담당).
Auth(최소): 닉네임·아이디(내부 유니크 형식검증) 입력 → ProfileRepository(mock) 저장.
OnboardingFeature.RootView로 노출. 이 패키지 밖 수정 금지.
```
**점검:** 슬라이드·닉/아이디 저장(mock).
**커밋:** `feat(onboarding): 4-step + auth`

## S2 — 홈 (지도)

**Codex 프롬프트(HomeFeature 폴더에서 실행):**
```
지금 위치는 Packages/HomeFeature. 이 패키지 안에서만 작업.
홈 지도 화면을 구현:
- MapKit(Map)으로 지도 표시. 수집한 생물을 발견 위치에 마커로(SightingRepository/CollectionRepository, mock).
  마커는 종 썸네일 + 라벨 칩.
- 하단 가로 개체 카드: 썸네일·카테고리·이름·거리/상태(LocationService mock로 현재 위치, 거리 계산).
- DesignTokens 사용(라이트 지도 톤). 좌표 없는 기록은 목록으로 폴백.
데이터는 CorePackage 프로토콜로만. HomeFeature 밖 수정 금지.
HomeFeature.RootView로 노출(App 셸이 나중에 꽂음).
```
**점검:** mock 좌표로 마커·카드 렌더.
**커밋:** `feat(home): map + creature markers + card`

## S3 — 폴리시 + 실구현 연결 (통합 때)

**Codex 프롬프트:**
```
통합 브랜치에서 HomeFeature/OnboardingFeature가 승아 실구현 주입으로 동작하는지 확인.
깨지면 (a) 내 패키지 내부면 수정, (b) 계약/실구현이면 승아에게 이슈(직접 수정 금지).
엣지: 수집 0건일 때 홈 빈 지도 안내, 좌표 없는 기록 목록 폴백, 온보딩 재진입 방지. 시안과 간격/색/폰트 비교.
```
**점검:** 실데이터로 홈·온보딩 동작 + 시안 일치.
**커밋:** `polish(home,onboarding): real data + edge cases`
