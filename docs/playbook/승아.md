# Cature 빌드 플레이북 — 승아 (Claude Code)

> 소유: **초기 세팅 + 발견 플로우 + AR 체험.** 도구: **Claude Code**(루트 `CLAUDE.md`).
> 원칙: 한 번에 한 STEP → 스샷/실기기 검증 → 커밋. Core는 나만 수정. S3 끝나면 **G1(v0-contracts)** 태그 → 팀원 시작.

---

## S0 — 스캐폴드 + 헌법

**목적:** SwiftUI 앱 + SPM 패키지 골격 + 컨텍스트 파일.

**프롬프트(복붙):**
```
Cature라는 iOS 앱(SwiftUI, iOS 17+, iPhone 14 Pro 타깃)을 새로 스캐폴드해줘.
- 앱 타깃 'CatureApp'은 얇게: 탭 셸과 네비만.
- SPM 로컬 패키지 폴더 Packages/ 를 만들고 빈 패키지 골격을 생성:
  CorePackage, DataPackage, ServicesPackage, DesignTokens, DiscoveryFeature, ARFeature,
  DexFeature, HomeFeature, MinigameFeature, OnboardingFeature. 각 Package.swift 포함.
- CorePackage는 의존 0. 나머지 Feature는 CorePackage에만 의존하도록 Package.swift 설정.
- 루트에 CLAUDE.md(내 헌법)와 AGENTS.md(팀 공통 규칙) 초안을 docs/ 규칙대로 작성.
- .gitignore에 xcuserdata, .DS_Store; Assets3D/는 Git LFS 대상으로 .gitattributes 추가.
로직/화면은 아직 만들지 마. 골격과 빌드 성공까지만.
```
**점검:** 빈 앱이 빌드·실행됨. 모든 패키지가 CorePackage에만 의존.
**커밋:** `chore: scaffold app + SPM packages + context files`

---

## S1 — Core: 모델 · 프로토콜 · Mock

**목적:** 병렬의 seam. 계약을 얼린다.

**프롬프트:**
```
CorePackage에 Cature 바이브코딩 PRD §2의 데이터 모델(Codable)을 그대로 구현:
UserProfile, Species, CoexistCard, AnalysisCandidate, Sighting, CollectionEntry.
그리고 프로토콜을 정의:
SpeciesRepository, SightingRepository, CollectionRepository, ProfileRepository,
LLMService, LocationService, CaptureService.
각 프로토콜의 Mock 구현도 CorePackage/Mocks에 만들어:
- MockLLMService.identify는 [카멜레온 0.78, 도마뱀 0.24, 버섯 0.02] 고정 반환,
  coexistCard는 카멜레온 샘플(필요: 나뭇가지/은신처, 방해: 만지기/오래 촬영) 반환.
- Mock 리포지토리는 메모리 배열로 동작(샘플 종 3~4개 시드).
docs/contracts.md 에 모델·프로토콜 요약을 표로 남겨(팀원용 SSOT).
```
**점검:** CorePackage 단독 컴파일 + Mock으로 간단 단위테스트 통과.
**커밋:** `feat(core): models + protocols + mocks + contracts.md`

## S2 — DesignTokens

**목적:** 세 기능의 룩 드리프트 방지 SSOT.

**프롬프트:**
```
DesignTokens 패키지에 Cature 토큰을 정의(PRD §7):
- Color: 라이트(지도)용 뉴트럴/화이트, 다크(카메라·분석·카드)용 딥그레이/블랙, accent.
- Typography: Pretendard 계열 대체 시스템 폰트 스케일(title/headline/body/caption).
- Spacing, Radius(라운드 카드), 그리고 재사용 컴포넌트: CardStyle, PillTabStyle, PrimaryButtonStyle.
SwiftUI View/ViewModifier로 노출하고, docs/tokens.md에 사용법을 짧게 문서화.
색/폰트는 임시값이라도 토큰으로만 접근하게(하드코딩 금지).
```
**점검:** 샘플 프리뷰에서 토큰 적용 확인.
**커밋:** `feat(tokens): design system seed`

## S3 — 앱 셸 · 탭 · 카메라 FAB · 라우팅 → **G1**

**목적:** 기능이 꽂힐 자리. 팀원 병렬 개시점.

**프롬프트:**
```
CatureApp에 하단 3탭 셸을 만들어: 홈 / 기능 / 마이. 우하단에 다크 원형 카메라 FAB.
각 탭·FAB는 지금은 placeholder 루트뷰(빈 화면 + 라벨)로 연결하되,
나중에 각 Feature 패키지의 루트뷰로 교체할 수 있게 라우팅 지점을 명확히 분리해줘
(예: HomeFeature.RootView, MinigameFeature.RootView 자리표시자).
DesignTokens의 PillTabStyle을 하단 탭에 적용. 로직은 넣지 마.
```
**점검:** 탭 전환·FAB 탭 동작(빈 화면). 팀원이 mock+토큰으로 자기 패키지 컴파일 가능.
**커밋 + 태그:** `feat(app): tab shell + camera FAB` → `git tag v0-contracts` → **팀원에게 시작 신호.**

## S4 — 로컬 저장 (경로 A)

**목적:** Repository 실구현.

**프롬프트:**
```
DataPackage에 CorePackage 리포지토리 프로토콜의 로컬 구현을 만들어(경로 A):
- UserProfile/상태: UserDefaults. Sighting/CollectionEntry: Codable JSON 파일(또는 SwiftData).
- 사진: 전달받은 임시 경로를 documents 하위로 복사하고 그 경로를 저장. 교체·삭제 시 옛 파일 정리.
- 저장 규칙은 PRD §3: 저장 시 Sighting 생성 + captureCount+1 + discovered=true, 달성률 = 발견종수/전체종수.
now(시간) 주입 가능하게 만들어 경계 단위테스트도 추가.
CorePackage/Mocks는 유지(교체는 통합 때).
```
**점검:** 저장→재실행 후 유지, 달성률 계산 테스트 초록.
**커밋:** `feat(data): local repositories (path A)`

## S5 — LLM 서비스 (식별 + 공존 카드)

**목적:** 발견의 두뇌.

**프롬프트:**
```
ServicesPackage에 LLMService 실구현을 만들어(PRD §5):
- identify(image): 멀티모달 API 호출 → 엄격 JSON(후보 배열: displayName, speciesId?, confidence) 파싱. 실패/저확신 안전 처리.
- coexistCard(speciesId): 소개1줄+필요2~3+방해2~3 생성 → 종별 캐시(로컬). 큐레이션 캐시 우선.
- 프롬프트는 data/prompts/identify.txt, coexist.txt 로 외부화.
- API 키는 로컬 config(비커밋, .gitignore). 프로덕션 프록시는 TODO 주석.
가드레일: 사람/무생물/판독불가 → 낮은 confidence 또는 '생물 아님' 분기.
```
**점검:** 실사진 몇 장으로 후보·카드 확인. 오프라인/실패 경로 확인.
**커밋:** `feat(services): LLM identify + coexist card`

## S6 — 위치 · 카메라 캡처

**프롬프트:**
```
ServicesPackage에 LocationService(CoreLocation: 좌표+역지오코딩 구/동명, 거부 시 좌표 없이 진행)와

Info.plist에 한국어 권한 문구: NSCameraUsageDescription, NSLocationWhenInUseUsageDescription, NSPhotoLibraryUsageDescription.
```
**점검:** 실기기에서 촬영·좌표 획득, 권한 거부 플로우.
**커밋:** `feat(services): location + capture`

## S7 — 발견 플로우 (내 화면)

**목적:** 카메라→분석→공존카드→수집연출 (PRD §4).

**프롬프트:**
```
DiscoveryFeature에 발견 플로우 화면을 DesignTokens 기반으로 구현:
1) 카메라(발견/체험 토글; 체험은 ARFeature 진입점으로 라우팅만).
2) 분석: 후보+정보 정확도 리스트, '인식 잘못됐나요? 다시 찍기'.
3) 공존 카드: 종 소개 + usdz 미리보기 자리 + 필요/방해 2블록 + 저장하기.
4) 수집 연출: 체크 + '○○을 발견했어요' + 촬영 N회 + 달성률 + 확인.
CaptureService·LLMService·SightingRepository·CollectionRepository를 주입받아 사용(실구현 연결).
```
**점검:** 촬영→저장까지 실기기 완주.
**커밋:** `feat(discovery): capture→analyze→coexist→collect`

## S8 — AR 체험 → **G2 확정**

**프롬프트:**
```
ARFeature에 RealityKit AR 체험을 구현:
- 카메라 '체험' 모드 → 수집(발견)한 종 중 usdz 보유 종 선택 → ARKit 평면 인식 → usdz 엔티티 배치.
- 제스처: 이동/회전/스케일(핀치). 빈 평면·조명 부족 오버레이 안내.
- CollectionRepository에서 수집 종 목록을 읽고, Assets3D의 usdz를 로드.
실기기(iPhone 14 Pro)에서 검증.
```
**점검:** 실기기 배치·조작 성공. 규칙 테스트 초록 → `v0.1` 태그.
**커밋 + 태그:** `feat(ar): usdz placement experience` → `git tag v0.1`

## S9 — 통합 · 골든패스 → **G3**

**프롬프트:**
```
App 셸에서 각 Feature 루트뷰를 실제로 배선: 홈=HomeFeature(예준), 기능=MinigameFeature(찬희),
마이=DexFeature(찬희), 카메라 FAB=DiscoveryFeature. 온보딩=OnboardingFeature(예준) 진입.
각 Feature의 mock 주입을 Data/Services 실구현으로 교체.
골든패스 통합테스트: 온보딩→홈→발견→분석→공존카드→저장→도감/지도 반영→체험→미니게임 진입.
깨지는 접합부는 계약 관점에서 최소 수정(팀원 패키지 내부는 오너에게 요청).
```
**점검:** 골든패스 초록.
**커밋 + 태그:** `feat: integrate features + golden path` → 데모 준비 → `v0.2`

## 내 고정 규칙 (CLAUDE.md에도 박기)
- 요청한 STEP 범위만. 팀원 Feature 패키지 수정 금지(계약 변경은 내가 contracts.md로 공표).
- 한 번에 하나 → 검증 → 커밋. AR·촬영·위치는 실기기.
- 시각 조정은 정확한 값으로. 측정 스크립트 금지.
