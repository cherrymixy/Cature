# Cature — 3인 협업 프로세스

> 승아가 **초기 세팅 + 발견 플로우 + AR**을 SSOT로 얼리고, 그 위에 찬희(도감·홈)·예준(미니게임·온보딩)이 기능을 병렬로 얹는다.
> 도구가 다르다: **승아 = Claude Code, 찬희·예준 = Codex.** 스코프는 SPM 패키지 + 컨텍스트 파일로 이중 펜싱.

---

## 0. 모델 한눈에

```
[승아 · Claude Code]  스캐폴드 → Core(모델·프로토콜·Mock) → 토큰 → 앱 셸  ══► v0-contracts
                       (이후) 로컬 저장 → LLM 서비스 → 발견 플로우 → AR
[찬희 · Codex]                    └─(v0-contracts 후)─► 도감 → 홈
[예준 · Codex]                    └─(v0-contracts 후)─► 온보딩 → 미니게임
                                                          ▼
                                                   통합 → 골든패스 → 데모
```

**핵심:** `v0-contracts`(계약+토큰+셸) 초록 전엔 병렬 시작 금지. 이게 관문.

---

## 1. 오너십 & 폴더

| 오너 | 도구 | 소유 패키지 | 읽는 계약 |
|---|---|---|---|
| 승아 | Claude Code | Core·Data·Services·DesignTokens·DiscoveryFeature·ARFeature·App | (원본 소유) |
| 찬희 | Codex | DexFeature·HomeFeature | Collection·Sighting·Species·Location |
| 예준 | Codex | MinigameFeature·OnboardingFeature | Collection(읽기)·Profile |

- **Core/Services는 승아만 수정.** 팀원이 프로토콜을 바꾸려면 → 승아에게 요청(계약 변경 = 이벤트).
- 팀원은 **자기 패키지 밖을 건드리지 않는다.**

---

## 2. 도구 분업 & 컨텍스트 파일 (제일 중요)

Codex와 Claude Code는 읽는 지시 파일이 다르다. 이걸 이용해 스코프를 못 섞게 만든다.

- **루트 `CLAUDE.md` (승아·Claude Code):** 승아 헌법 — "너는 Core/Data/Services/토큰/셸/발견/AR 오너. 팀원 Feature 패키지는 건드리지 마."
- **루트 `AGENTS.md` (공통·Codex가 읽음):** 전 팀 공통 규칙 — 계약은 `docs/contracts.md`, 토큰은 `DesignTokens`만, PR 규칙, "Core/Services 수정 금지".
- **패키지별 `AGENTS.md` (찬희·예준 펜스):** Codex는 **작업 디렉터리에서 루트로 올라가며 AGENTS.md를 병합**하고 **가까운 파일이 우선**한다. 그러니 각 Feature 폴더에 `AGENTS.md`를 둬서 "이 패키지 안에서만 작업. 다른 Feature·Core 수정 금지. 토큰 참조. mock으로 컴파일 확인." 을 박는다.
  - 예: `Packages/DexFeature/AGENTS.md`(찬희), `Packages/MinigameFeature/AGENTS.md`(예준).
  - Codex를 **해당 패키지 디렉터리에서 실행**하면 그 폴더 규칙이 최우선 적용된다.
- **한 줄 요약:** 승아는 CLAUDE.md 한 장, 찬희·예준은 루트 AGENTS.md(공통) + 자기 패키지 AGENTS.md(펜스) 두 장.

> Codex 팁: `AGENTS.md`는 32KB에서 잘림 → 길면 패키지별로 쪼갠다. 프롬프트(사람이 직접 친 지시)가 AGENTS.md보다 우선하므로, 프롬프트에도 "네 패키지 밖 금지"를 매번 한 줄 넣는다.

## 3. 기능 분할에서도 남는 공유 표면 3개 (= 승아가 먼저 씨앗)

1. **계약**(모델·프로토콜·Mock) → `CorePackage`, `docs/contracts.md`.
2. **디자인 토큰**(색·타이포·컴포넌트) → `DesignTokens`. 안 그러면 도감/홈/미니게임 룩 드리프트.
3. **앱 셸/네비**(탭 + 카메라 FAB) → `App`. 기능은 **루트뷰만 노출**, 셸이 한 줄로 꽂는다.

이 셋을 `v0-contracts`에 담아 먼저 커밋 → 팀원 병렬 시작.

## 4. GitHub / Xcode 규약

- **main 보호**, 직접 푸시 금지, **PR로만**. PR = 작은 슬라이스(한 화면·한 규칙).
- **브랜치 프리픽스:** `seunga/`, `chanhee/`, `yejun/`. 하루 이상 안 묵히고 자주 통합.
- **태그:** `v0-contracts` → `v0.1`(발견 스파인+로직) → `v0.2`(데모).
- **SPM 로컬 패키지**로 `project.pbxproj` 충돌 제거(파일 추가가 프로젝트 파일을 안 건드림). `.xcodeproj`는 최소화.
- **usdz/대용량 이미지 = Git LFS.**
- **PR 리뷰:** Core/계약을 건드리는 PR은 **승아 필수 리뷰**. Feature 내부는 오너 승인.

## 5. 페이즈 (누가 · 통과 기준)

### PHASE 0 — 셋업 (다 같이, 코드 X)
- Cature PRD 확정 · `CLAUDE.md`·루트 `AGENTS.md` · 레포/SPM 구조 · Git 규약 합의.
- **통과:** 각자 자기 패키지 경계와 "Core는 승아만"을 말로 설명 가능.

### PHASE 1 — 계약 + 씨앗 (승아)  ★관문
- 승아: `CorePackage`(모델·프로토콜·**Mock**) + `DesignTokens` + `App` 셸 커밋 → `v0-contracts`.
- **통과:** 찬희·예준이 **Mock + 토큰**만으로 자기 패키지 컴파일·실행(빈 화면이라도 돎).

### PHASE 2 — 병렬
- **승아:** 로컬 저장 → LLM 서비스 → 발견 플로우 → **AR** (`v0.1`).
- **찬희:** 도감 → 홈. **예준:** 온보딩 → 미니게임. 각자 Mock 위에서.
- **공통:** 자기 패키지, 매일 통합, 계약 변경은 싱크에서만.

### PHASE 3 — 통합 & 폴리시
- Mock → 승아 실구현 교체. 셸에 기능 루트뷰 배선. **골든패스 한 바퀴**(온보딩→홈→발견→분석→공존카드→저장→도감→체험 + 미니게임 진입). 폴리시.
- **통과:** 골든패스 통합테스트 초록 + 시안 vs 빌드 일치.

### PHASE 4 — 데모
- 빈 상태·권한·경계·기기 엣지 + 데모 리허설 → `v0.2`.

## 6. 운영 규칙

- **Mock-first:** 안 만들어진 의존은 mock. 프로토콜엔 항상 Mock.
- **계약 변경 = 이벤트:** 승아가 싱크에서 공표 + 승인. 몰래 바꾸지 않기.
- **데일리 싱크 10분:** 계약 변경·블로커만. 통합 담당(승아)이 main 초록 유지.
- **한 번에 하나 → 스샷/실기기 검증 → 커밋.**

## 7. 리스크 → 규칙

| 이렇게 깨진다 | 가드레일 |
|---|---|
| 계약 안 굳었는데 병렬 시작 | `v0-contracts` 초록 전 병렬 금지 |

| `pbxproj` 충돌 | SPM 로컬 패키지 |
| 며칠 각자 달리다 통합 지옥 | 데일리 통합 + 승아 main 관리 |
